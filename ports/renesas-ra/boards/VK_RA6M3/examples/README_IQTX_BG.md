# RA6M3 IQTX — експериментален baseband предавател

## Актуално — 2026-09-08: AM/SSB аудиоконтроли

AM HOME и TX BACKEND имат **AF gain / AM depth / TX LEVEL**. USB/LSB имат
**AF gain / TX LEVEL**; FM запазва AF gain / DEV / TX LEVEL. RX VOL/AGC не
управляват предавателя. Избраният плъзгач остава вдясно след затваряне.
Съответстващите Python и RadioOnly firmware са качени и прочетени обратно.
Кратък цифров AM→USB→LSB→FM тест потвърди контекста, LEVEL0/40, непрекъснат
FILE owner и AF кадри. AF gain/depth имат host проверки; аналогов тест няма.
Протокол: `tests/tx/results/tx-audio-board-20260908.log` (спрямо ports/renesas-ra).

| Настройка | Какво променя |
| --- | --- |
| AF gain | Усилва подаденото аудио x0..x16 преди ограничителя на модулатора. Не е AGC. |
| AM depth | 0..100% относително изменение на носещата при аудио +/-2048 кода и gain x1. По-тих вход дава по-малка дълбочина. |
| TX LEVEL | Пропорционален цифров размах, не измерена RF мощност. 0% дава I/Q нулевите кодове; 100% използва допустимия размах за режима. |

При стандартни i_zero=q_zero=2048 AM използва carrier amplitude 0..1023,
за да остави място за 100% модулация; SSB/FM използват пик 0..2047.
AM 50% depth не се променя при местене на LEVEL. Прекомерният AF gain може
да ограничи модулацията; намаляването само на LEVEL не премахва това изкривяване.
AF gain=0 или AM depth=0 оставят немодулирана AM носеща; LEVEL=0 премахва и нея.

```python
tx = IQTX(mode=IQTX.AM, audio_gain=100, am_depth=50, amplitude=409)
tx.start()
tx.audio_configure(audio_gain=100, am_depth=80, amplitude=600)
# За USB/LSB: същите audio_gain и amplitude; am_depth не се използва.
```

Без `audio_gain` native API запазва стария AM/SSB режим. Новият интерфейс
го задава изрично. При MIC AM таблицата се променя след checked stop и
преди start, в съществуващата алокация; възможно е кратко прекъсване.
При FILE AM и SSB се сменят само скаларните параметри между семплите:
няма restart, връщане на файла в началото или нулиране на Hilbert историята.
UI заявките са отложени към worker, последователните slider стойности се обединяват.
Параметрите се приемат само след успех и се записват в dataflash след връщане RX.

FILE AM вече няма LUT: native заявката за нея е 0 вместо 8192+8191=16383 B.
MIC AM остава с 8192-B таблица и подравняване за DTC. Една C формула обслужва
двата пътя. Това е премахната алокация, не измерена обща свободна RAM на платката.

R:USB/R:LSB получават `file_gain=75` преди ограничителя на FILE декодера,
независимо дали изходната модулация е AM или SSB. R:AM/R:FM използват 100.
Това интегрира предходната RAM проба за запас. Кратките цифрови USB/LSB тестове
на платката отчетоха 0 DSP clips; това не гарантира липса на clipping за
произволен файл и не замества продължителен тест. Микрофонът
не се променя от `file_gain`. Scope показва входния AF, не RF мощността.

## Предходен етап — 2026-09-08: контекстен TX HOME

Локалният `sdr_single.py` вече позволява AM/USB/LSB/FM, честота и стъпка
директно от HOME при TX. Редът остава << / mode-FIX-step / >> / - / +.
`FIX` означава фиксиран native TX филтър; RX bandwidth не се прилага в TX.
Изборът е worker-side checked stop → Si5351 ×1 → configure → start.
При връщане се възстановяват RX mode/frequency/step и RX clock множителят.

Бутонът на мястото на AGC избира MIC или наличен R:AM/R:USB/R:LSB/R:FM.
FILE декодирането е независимо от TX модулацията: например R:AM може да
дава AF към USB предаване. Scope показва този AF; FILE замества MIC изцяло.
LOOP се запазва; всяко преконфигуриране започва файла отначало. BACK не спира TX.
RX VFO алтернативите се скриват в HOME и са read-only в TX keypad/routing.

UI етапът вече е включен в каченото приложение и краткия цифров тест по-горе.
При меню/контрола са отчетени преходни FILE underruns; след 1200 ms
изчакване следват 2 s с 0 нови underruns за всеки режим. Това не е доказателство
за непрекъснато аудио през менюта или за аналогови DAC/CLK/RF. Native TX GEN,
настройваем TX филтър и аналогова валидация остават отделни задачи.
Пълният текущ план и история са в каноничните `ra6_sdr_next_steps.md` и
`ra6m3_done.md`; техните Git snapshots са в `project-status/`.

## Гласов FM — 2026-09-07, source/host/build, без ново качване

`IQTX(mode=IQTX.FM)` вече избира гласов C път. Постоянният AGT такт задейства
ADC0; ограничен C callback премахва постоянната съставка (30 Hz), филтрира звука
с Butterworth low-pass 3 kHz, прилага MIC усилване и ограничава пиковата девиация.
Фазата се натрупва с 32 бита. Същият 1-KiB LUT и линейна интерполация генерират
I/Q; няма Python или heap работа на семпъл. Състоянието е в общия CW/SSB workspace.
Аналоговият anti-alias филтър преди ADC остава необходим; цифровият не го заменя.

| Параметър | Значение | Диапазон |
|---|---|---|
| `deviation_hz` | Пиково отклонение от носещата при пълен звуков вход | 100..5000 Hz |
| `mic_gain` | Микрофонно усилване; 100 означава x1 | 0..1600% |
| `amplitude` | Пикова амплитуда на I/Q DAC, независима от девиацията | 0..допустимия размах спрямо I0/Q0 |

Скалата на девиацията използва действителния timer период. При unity MIC
вход +/-2048 ADC кода след филтриране съответства на зададената девиация;
по-слаб сигнал дава пропорционално по-малка девиация. Ограничителят не е AGC.
Зададени +/-5 kHz не означават автоматично +/-5 kHz при тих микрофон.
При тишина има немодулирана комплексна носеща; amplitude0 премахва и нея.
След внезапна промяна на постоянния вход има затихващ преход, не моментална
идеална компенсация. Pre-emphasis не е реализирана в този профил.

```python
tx = IQTX(mode=IQTX.FM, deviation_hz=2500, mic_gain=100, amplitude=800)
tx.start()
tx.fm_configure(deviation_hz=4000, mic_gain=200, amplitude=600)
# Промяната не рестартира фазата или филтрите.
print(tx.status())
tx.stop()
tx.deinit()
```

В HOME при FM TX десният плъзгач е `TX`; натискане върху заглавието отваря
съществуващия inline панел с **MIC / DEV / TX LVL**. Единичният checkbox избира
кой контрол остава вдясно. MIC е x0..x16, DEV е +/-0.1..5.0 kHz, TX LVL е0..100%.
UI default TX LVL40% означава819 DAC кода; native API default остава800 кода.
При връщане в RX се възстановява избраният приемен контрол и стойностите му.
RX AGC/VOL не се представят като управление на предавателя. В другите TX режими
HOME показва `TX` с действително конфигурираното I/Q ниво, само за четене:
засега промяна на нивото по време на работа е реализирана единствено за FM.

**BACKEND също е контекстен.** Натискане на SDR отваря съществуващото меню
PLL/VFO routing + CAL. Долният бутон показва `BACKEND RX >` или `BACKEND TX >`:

- RX отваря досегашния VERIFY с приемните DSP блокове и TESTER.
- TX отваря TX BACKEND за работещата модулация. При FM има същите MIC, DEV и
  TX LEVEL, както в HOME; `+/-` променят една стойност, задържането я повтаря.
  Показват се C времевият бюджет, максимален звуков пик, DC оценка, ADC крайни
  кодове, ограничаване и двата DAC enable бита. Това са цифрови показатели,
  не измерване на RF мощност или аналогово качество.
- AM/CW/USB/LSB отварят TX конфигурация и диагностика за четене, не RX VERIFY.
  Липсващите live setters не се заменят с привидно работещи RX контроли.

BACK затваря само настройките и **не спира TX**. PLL/VFO и CAL настройките са
неактивни при TX, защото тази итерация не реализира управление на предавателния
RF осцилатор. ROUTE и BACKEND не заемат RAM едновременно. При смяна на
собственика RX/TX отвореният BACKEND се освобождава, без да остава стар контекст.

TX стойностите се пазят отделно (`txdev`, `txmic`, `txlevel`) в SDR dataflash
записа, не във външния QSPI файлов дял. Записът се отлага до връщане в RX и
изтичане на обичайния60-s debounce; при загуба на захранване преди това
последните промени не са запазени. Няма автоматичен TX след boot.

`status()` отчита `cpu_dsp`, семпли, C цикли, `adc_rails`, `dc_estimate`,
`audio_peak`, `dsp_clips`, приложените параметри и отделни `i_enabled`/`q_enabled`.
Общият `outputs_enabled` вече изисква и двата DAC бита. По-старите HIL отчети
с общ флаг не доказват състоянието на всеки изход. HOME `PK` е максимум след
start, `ADC` показва достигане на крайните ADC кодове, `TIME` — C deadline,
`CLIP` — звуков ограничител. Това не е аналогов измерител или моментен VU meter.

Хост: **15 групи / 7 055 959 C проверки — PASS**, RX/TX и FM UI/persistence
тестове — PASS. `build_sdr.ps1 -OpenCV Off -Jobs 16` — PASS; CV2 символи0,
heap290816 B, QSPI12/4 непроменен. Native TX state1524 B (+16 B),
BIN1585016 B (+2072 B спрямо качения SSB). Няма измерено FM ISR време на
платката, аналогова девиация, RF спектър или UI визуална проверка за този build.

За стария автономен DOC експеримент изрично използвайте `fm_gain=1/2` без
`deviation_hz`, или `deviation_hz=0`. Той няма новото филтриране/ограничител
и `fm_configure` не се прилага за него. Старите descriptor тестове остават raw.

## Ресурси

| Ресурс | Предназначение |
|---|---|
| P001 / ADC0 AN001 | Микрофонен вход за AM/FM/USB/LSB; десноподравнени 12-bit резултати |
| P014 / DAC0 | I; `i_zero=2048` по подразбиране |
| P015 / DAC1 | Q; `q_zero=2048` по подразбиране |
| Един свободен AGT0/1 | Постоянен семплиращ такт; автоматична reservation |
| ADC0_SCAN_END / DTC / DOC | AM/raw-FM sample chain; не CPU обработка |
| ADC0_SCAN_END / C DSP | Гласов FM и USB/LSB: C callback за всяко измерване, без Python |
| AGT interrupt / DTC | CW рампа и безкрайно задържане |
| CW GPIO | **Няма назначен порт**; `key(True/False)` е команда |

ADC/DAC ресурсите са изключителни до успешно `deinit()`, включително след
`stop()` и при частично неуспешен init. Съществуващи IQADC/AudioADC и включени
DAC/Mixer трябва да се деинициализират преди IQTX. Друг AGT може да остане за UI.
Не пренастройвайте P001/P014/P015 чрез Pin, mem32 или друг native код при TX owner.

P001 се нуждае от външна микрофонна схема с подходящ gain, DC bias и anti-alias
филтър. `adc_mid` е **измереният** ADC код при тишина, не обещание за2048.
И двата DAC са без вътрешния изходен усилвател: външният I/Q вход трябва да има
подходящ висок импеданс/буфер и реконструкционен филтър. Не свързвайте директно
50-ohm товар. Common-mode, допустими напрежения и RF модулатор още не са определени.

## API — само изричен старт

```python
from machine import IQTX

tx = IQTX(mode=IQTX.FM, rate=44000, amplitude=800,
          adc_mid=2048, i_zero=2048, q_zero=2048, fm_gain=2)
print(tx.status())  # само подготовка: DAC нулеви I/Q нива, timer е спрян
tx.start()          # ИЗРИЧНО разрешение за baseband генерация
# Python/UI може да работи; няма sample callback или buffer-refill задача.
tx.stop()           # checked stop; двата DAC се връщат към i_zero/q_zero
tx.deinit()         # освобождаване; DAC изходите се изключват
```

За CW:

```python
tx = IQTX(mode=IQTX.CW, amplitude=800, ramp_samples=220)
tx.start()          # започва с key-up / нулев комплексен сигнал
tx.key(True)       # подава рампа; не чака нейните220 семпъла да завършат
tx.key(False)      # рампа от действителния последен DAC код, включително при обръщане
tx.stop()
tx.deinit()
```

Нормализираната raised-cosine форма се изчислява при init. Командата `key()`
спира и проверява текущия пренос, мащабира таблицата с цели числа и пуска DTC.
Това е ограничена работа при управление, **не нулев брой CPU инструкции**.
Няма изчакване на цялата рампа и няма CPU обслужване на семплите/края ѝ.
Измерени `key()` извиквания на RA6M3: **1384–1412 us** при тестваните 8/44 kHz
настройки. Това е около 1.4 ms синхронно управление, не нулево задържане и не
доказана горна граница за всички условия. Checked stop използва съществуващия
bounded AGT stop и отделни ограничени ADC/DTC проверки; при повреда може да хвърли.

Параметри: CW/AM/raw-FM `rate=8000..48000` (default44000). Гласов FM изисква
също `2*(deviation_hz+3000) < actual_rate`; това е предпазна граница, не RF маска.
USB/LSB **само12000**,
избрано автоматично при пропуснат `rate` или `rate=-1`. Друг изрично зададен
SSB rate се отказва, защото би променил честотната характеристика на филтъра.
`fm_gain=1/2`, `ramp_samples=1..256`.
Амплитудата трябва да се побира спрямо нулите: CW `I0+A<=4095`, AM `I0+2A<=4095`,
FM/USB/LSB и двете нули позволяват `+/-A`. Невалидни настройки се отказват преди hardware init.
Смяна на режим: `deinit()` → нов IQTX; няма live rebuild на таблици.
При неуспешен constructor е достъпен `IQTX.release()` за повторен checked cleanup.

След AM/FM/USB/LSB TX по-старите самостоятелни `machine.ADC` обекти са невалидни:
създайте ги отново след `tx.deinit()`. По време на TX получават `EBUSY`, а при
остарял ADC epoch — `ENODEV`; така няма скрит прочит на изключен/преконфигуриран ADC.

## Реален алгоритъм и ограничения

- **CW:** I=положителна огъваща, Q=0. DTC NORMAL рампа преминава чрез самопроменяща
  се chain към REPEAT1 hold. Краят не изисква ISR. `stop()` е незабавно спиране,
  не плавен key-up; за нормално ключуване използвайте `key(False)`.
- **AM:** snapshot ADC → DOC формира `2*ADC` → адресира предварително изчислена
  таблица: `DAC_I=I0+clamp(A+ADC-adc_mid,0,2*A)`, `DAC_Q=Q0`. Таблицата има
  4096 `uint16` стойности и DTC веригата използва 7 дескриптора.
  Ограничаването пази диапазона, но води до изкривяване; аналоговият gain трябва
  да държи полезния звук извън clipping. При default A800 пълна модулация е ±800ADC кода.
- **Raw FM (изричен fm_gain):** `phase=(phase+gain*(ADC-adc_mid)) mod65536`, `I=A*cos(phase)`,
  `Q=A*sin(phase)`. DOC натрупва всички 16 фазови бита; горните 8 избират един от
  256 квадратурни индекса. Компактната таблица е от две последователни `uint16`
  равнини: I при offset `0x000`, Q при offset `0x200`. Gain 1/2 използва съответно
  14/15 DTC дескриптора. ADC се чете еднократно в RAM; ACE е изрично изключен.
- **USB/LSB:** 255-коефициентен комплексен FIR филтър за глас 300..3000 Hz,
  при 12 kHz измервания от P001. USB оставя положителните честоти в `I+jQ`;
  LSB обръща знака на Q и оставя отрицателните. Това е цифровата конвенция:
  реалният RF резултат зависи и от знаците/свързването на външния смесител.
  Симетричният I и антисиметричният Q имат еднакво закъснение 127 семпъла
  (10.583 ms). Историята е общ непрекъснат поток, не се нулира при всяка порция.
  Първото измерване запълва историята, за да няма преход от постоянния входен bias.
  Q15 означава цели коефициенти, мащабирани с 32768; няма float или heap алокации
  при обработката. ADC кодов размах ±2048 съответства на зададената амплитуда A.
  Общ ограничител намалява I и Q едновременно при претоварване и увеличава
  `dsp_clips`; това предпазва DAC диапазона, но не прави претоварения звук линеен.

Динамичната LUT памет е различна за всеки режим:

| Режим | LUT | Подравняване | Максимална MicroPython алокация | DTC дескриптори |
|---|---:|---:|---:|---:|
| CW | 0 B | — | 0 B | режимът не използва LUT банка |
| AM | 8192 B | 8192 B | 16383 B | 7 |
| FM gain 1 | 1024 B | 1024 B | 2047 B | 14 |
| FM gain 2 | 1024 B | 1024 B | 2047 B | 15 |
| USB/LSB | 0 B динамична LUT | — | 0 B LUT allocation | C ISR, без DTC/DOC chain |

SSB коефициентите са 510 B във вътрешния code flash. Историята и служебните
полета са 520 B и споделят съществуващия CW workspace чрез union; не се добавя
нов голям RAM буфер. Двете форми не могат да работят едновременно.
Таблицата описва LUT алокацията, не целия размер на MicroPython TX обекта.

Оригиналният allocation обект остава GC root през целия owner lifetime. При
недостатъчна/фрагментирана памет се получава `MemoryError`; след него
`IQTX.release()` изчиства запазения частичен owner. Няма скрит CPU fallback.

При PCLKB60MHz AGT брои с30MHz. Този backend закръгля към най-близкия делител:
заявени44000Hz →682 броя → `43988.2697947Hz` (изчисление, не измерване).
FM девиацията е `actual_rate*gain*(ADC-adc_mid)/65536`. Не се записва микрофонният
код в таймерния период, така че няма нелинейността `f ∝ 1/period`.

DAC записите са последователни — DTC chain за AM/FM, C callback за USB/LSB.
Това **не е доказателство
за едновременен аналогов latch**. Изходният skew и потискането на образа остават HIL задачи.

## Аварии и граница на безопасност

Неочакваният callback спира източника по заявка, забранява собствената IRQ/DTC
активация и изключва DAC outputs. Не изпълнява cleanup в ISR. За USB/LSB нормалният
ADC callback **изпълнява C DSP** — не се представя за нулево CPU натоварване.
`dsp_last_cycles/max_cycles` измерват обработката от прочита на ADC до DAC записите.
`dsp_budget_cycles` е един семплов период в CPU цикли. При превишаване се задава
грешка `RA_TX_ERROR_DSP_DEADLINE` и DAC се изключват. Тези числа не включват целия
IRQ вход/изход и не доказват липса на пропуснати прекъсвания или джитър.
`unexpected_callbacks` е брояч на callback delivery, не универсален брояч на всички
spurious ISR entries. `quiesced=True` се задава само след успешно checked спиране;
`running` при fault не трябва да се използва самостоятелно като доказателство.
`error!=0` изисква stop/release и проверка, не автоматичен рестарт.

При timeout паметта и собствеността се запазват. Soft reset първо спира TX; ако
това не се потвърди, преминава към hardware reset преди GC. Изключен DAC може да е
високоимпедансен; DAC neutral/disable **не замества външен RF mute/PTT interlock**.
Такъв GPIO/аналогова защита не е зададен и не е реализиран.

## RX/TX управление от SDR UI

Съществуващият горен десен бутон е единствената заявка за смяна `RX ↔ TX`:

- от RX заявява контролирано преминаване към TX; от TX заявява връщане към RX;
- докато преходът не е завършил, бутонът показва междинно състояние; отказът се
  показва като грешка, а не като привидно успешно превключване;
- TX е разрешен за `CW`, `AM`, `FM`, `USB` и `LSB`; друг режим се отказва
  преди освобождаване на приемника;
- активни TESTER или FILE блокират TX заявката — операторът първо ги изключва;
- при USB/LSB UI следи `dsp_samples`. Ако броячът не напредва, заявява checked
  спиране и връщане към RX. Това е бавна контролна защита, не хардуерен RF interlock;
- това превключва само baseband I/Q ресурси. Няма реализирано TX LO routing,
  PA enable, RF relay, хардуерен PTT/mute или външен RF interlock.

UI handoff е проверен и на платката за USB/LSB, както е описано в началото.
Това не е аналогов или RF тест и не пренася автоматично резултата към AM/FM/CW.

## Проверки и следващ етап

`tests/tx/run_host_tests.py` компилира действителния `ra_tx_core.c` с GCC/Clang.
Последен резултат: **15 групи, 7 055 959 проверки — PASS**. Проверките включват
режимните размери/подравнявания, всички alignment residues, AM compact таблицата
и FM planar адресирането за всички 65536 фазови стойности. DOC/SAR случаите са
host модели, не изпълнен RA6M3 DTC.

SSB тестовете обработват истинските DAC кодове от C функцията: 56 USB/LSB тона
300..3000 Hz, най-лошо цифрово потискане на противоположната лента **67.85 dB**.
Това не е RF измерване. Проверени са DC, филтърно закъснение, извънлентови тонове,
граници на DAC, претоварване, USB/LSB conjugation, рестарт и идентичност при
различни размери на входните порции. Средната грешка 0.2 DAC кода при 2400 Hz е
от закръглянето; постоянен вход се отхвърля точно. Генераторът на коефициентите
`tests/tx/gen_ssb_coeffs.py --check` проверява възпроизводимостта и int32 границите.
Метод: [комплексен филтър за една странична лента](https://www.dsprelated.com/freebooks/sasp/Hilbert_Transform_Design_Example.html).

`test_sdr_tx_switch.py` минава host RX→TX→RX за всичките пет режима,
отказ при TESTER/FILE/tuning, освобождаване след грешка и SSB/FM stall guard.
`test_sdr_fm_controls.py` проверява трите FM контроли, отказ без промяна на
запазените стойности, връщане в RX и отложен flash запис с хост заместители.
Изпълнява и действителния Python път SDR -> ROUTE -> BACKEND RX/TX, callback-ите
на FM редовете, BACK без спиране, забрана при преход и почистване след
MemoryError. Widget заместителите не доказват визуалния layout или touch на панела.

SSB build: `build_sdr.ps1 -OpenCV Off -Jobs 16`, съществуващата `build-VK_RA6M3`.
BIN 1 582 944 B, SHA-256:
`b36ac6b23ec9598b1bd033ce8269eddc27ba266ae724ba874274d8539c1f78d2`.
Heap 290 816 B, QSPI 12/4 MiB, CV2 символи 0. Новият native TX state е 1508 B
срещу 1484 B в предходния качен образ: +24 B за диагностиката, без нов LUT heap.

етапът е само source/build; качването, обновеният MPY и цифровите SSB проверки

5. Отделни fault injection тестове: stop timeout и active-TX soft reset; по-широко
